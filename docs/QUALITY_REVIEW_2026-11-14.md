## 数学独立核查

原题最小角 A 满足 0<A≤60°。因 `tan A` 是整数，且 0<tan A≤√3<2，因此 tan A=1，A=45°。从 `A≤B≤C` 和 `B+C=135°` 推出 B,C 都为锐角（C=90° 时 tan C 无定义）。记 b=tan B,c=tan C，则 `(b+c)/(1-bc)=-1`，即 `(b-1)(c-1)=2`，结合 1≤b≤c，只有 b=2,c=3，总和 6。迁移练习 1,2,4 不属于原题，已单独标明。

## 剩余限制与长期改进

1. PPT 的盒子边界测试不等价于字体实测：跨平台字体替换、裁剪与数学符号显示仍要人工看 PDF/PNG。
2. 教案 JSON 的数学正确性无法由当前通用代码形式化证明；每道新题必须单独进行定义域与推导核查。
3. 字幕估算时码不等于录制完成的音频；正式视频需要先使用 `retime_tts.py` 处理逐 cue 音频，再使用 `assemble_video.py`。不得把初始视频草稿标记为已完成音画同步。
4. 只有用户输入的截图原题时，不应伪造官方题库来源；原题转写与教学新增练习必须分开记录。
5. 尚未实现逐句动态演示/数学公式对象级动画；目前是一页一段的静态图片视频流程，可在后续迭代。
6. 代码只能阻断已列出的制作术语及其变体，不能保证识别一切可能的面向内部制作的指令，仍需要人工终审。

## 推荐发布门槛

- 数学证明由人员/模型独立复核，单独说明原题与拓展内容；
- Python 测试通过，PPT + notes + voiceover + SRT + timeline 严格一致；
- 无制作术语混入 PPT 和观众语言；
- 每页文字完整、无静默截断；PDF/PNG逐页预览；
- 生成真实音频后校准字幕并核验最终音频总时长；
- 依照发布时间检查抖音端的字幕安全区、阅读舒适度和公式清晰度。


## 第二轮视觉复核补丁

原 `type=triangle` 示意图标注 `A=45°`，但图形坐标的 A 夹角实际上约为 30°，还可能使 C 看上去成为钝角；这会削弱教学严谨性。已把示意图坐标修改为 A=(2.0,7.07)、B=(4.7,7.07)、C=(3.8,5.27)，由边的斜率保证 `tan A=1,tan B=2,tan C=3`，新增坐标几何回归测试并由 CI 重新生成全部页面。视频拼接器也修复了带单引号目录路径的 ffconcat 转义细节。


## CI 检查补强：音频测试不得隐式跳过

审核 GitHub Actions 运行日志时发现测试摘要为 `15 passed, 1 skipped`，音频测试因为 runner 缺少 FFmpeg 而没有真实执行。现已调整 workflow，在运行 `pytest` 之前安装 `ffmpeg` 并使用 `-rs` 报告跳过原因；把只有 `pass` 的占位测试改成了实际校验负数停顿参数的 CLI 负测试。正式验收应看到 **0 skipped**，否则不得声称 TTS 联调通过。
